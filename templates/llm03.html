Vulnérabilité démontrée !

Description : Le modèle a fourni une réponse incorrecte et potentiellement malveillante. C'est le résultat de l'empoisonnement des données d'entraînement. Un attaquant a inséré des données corrompues dans le jeu de données utilisé pour entraîner ou affiner le modèle. Cela peut être utilisé pour introduire des biais, créer des portes dérobées (comme dans cet exemple), ou dégrader les performances générales du modèle.

Comment se protéger :

  • Vérifiez les sources de données : Utilisez des données provenant de sources fiables et réputées.
  • Nettoyez et filtrez les données : Mettez en œuvre des processus rigoureux pour filtrer les données d'entraînement afin de supprimer les contenus malveillants, les biais et les informations personnelles identifiables.
  • Utilisez des "adversarial robustness techniques" : Entraînez le modèle à être résistant aux exemples contradictoires.
  • Effectuez des audits réguliers : Auditez et évaluez en continu les performances et le comportement du modèle pour détecter les anomalies qui pourraient indiquer un empoisonnement.
