LLM10: Laboratoire sur le vol de modèle

Objectif : Comprendre la menace du vol de modèle, où des attaquants peuvent voler des modèles de langage propriétaires, entraînant une perte financière, un avantage concurrentiel diminué et une atteinte à la réputation.

Le vol de modèle est l'exfiltration non autorisée d'un modèle d'IA. Contrairement aux vulnérabilités précédentes, il ne s'agit pas d'une attaque que vous pouvez directement "essayer" dans un simple laboratoire web. Il s'agit plutôt d'une menace pour l'infrastructure et la sécurité opérationnelle qui héberge le modèle.

Scénarios courants de vol de modèle :

  • Accès physique ou au réseau compromis : Un attaquant obtient un accès non autorisé au serveur où les poids du modèle sont stockés et les copie simplement.
  • Menaces internes : Un employé mécontent ou un initié compromis exfiltre le modèle.
  • Attaques par extraction de modèle : Des attaquants qui n'ont qu'un accès par API au modèle peuvent parfois reconstruire une approximation fonctionnellement équivalente du modèle. Ils le font en interrogeant l'API de manière répétée avec des entrées soigneusement sélectionnées et en utilisant les sorties pour entraîner un modèle de substitution.
  • Attaques par inversion de modèle : Dans certains cas, les attaquants peuvent utiliser la sortie du modèle pour déduire des informations sur les données d'entraînement, ce qui constitue une forme de vol d'informations, sinon du modèle lui-même.

Démonstration conceptuelle

Description : Le vol d'un modèle de langage de pointe représente une perte financière et stratégique significative. La recherche, le développement, la collecte de données et la puissance de calcul nécessaires pour entraîner ces modèles peuvent coûter des millions de dollars. Un concurrent qui vole un modèle peut reproduire les capacités d'une entreprise sans cet investissement. De plus, si le modèle a été entraîné sur des données propriétaires ou sensibles, le vol du modèle peut également entraîner une violation de données majeure.

Comment se protéger :

  • Contrôles d'accès stricts : Mettez en œuvre des contrôles d'accès stricts et à plusieurs niveaux pour les systèmes qui stockent et servent les modèles. Appliquez le principe du moindre privilège.
  • Chiffrement : Chiffrez les poids du modèle au repos et en transit.
  • Détection des intrusions : Utilisez des systèmes de détection des intrusions pour surveiller l'accès inhabituel aux fichiers du modèle ou aux serveurs d'hébergement.
  • Filigranage : Intégrez des filigranes dans les réponses du modèle. Ces filigranes peuvent aider à prouver la propriété si un modèle volé est découvert utilisé ailleurs.
  • Limitation du débit et surveillance des API : Pour vous défendre contre les attaques par extraction de modèle, mettez en œuvre une limitation de débit sur votre API et utilisez des algorithmes pour détecter les schémas de requêtes suspects qui indiquent une tentative d'extraction.
